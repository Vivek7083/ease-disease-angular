## What this is, in one paragraph

Angular v22 standalone/signals PWA, single scrollytelling homepage for **Ease
Disease**, a digestion-first functional-medicine practice. One fixed
full-viewport background "canvas" color crossfades as you scroll through a
sequence of `<section class="scene">` blocks (`CanvasStoryService` +
`appCanvasStop` directive) — sections themselves are transparent. Visual
language: warm ivory/parchment canvas, oxblood/terracotta/ember accents,
display serif (Fraunces) for headings, mono (DM Mono) for eyebrows/prices,
DM Sans for body. No dark-mode inversion panels anywhere — "seriousness" is
carried by the oxblood color itself, never by switching to a dark background.
Darkness is a **surface** (cards, overlays), never the page canvas.

Run: `npm start` → `ng serve`, this repo's sessions have consistently used
port 4300 (`npx ng serve --port 4300`) to avoid clashing with whatever else
might be on 4200. Build: `npx ng build --configuration production`.

## Design system — the actual tokens (don't invent new colors/spacing)

All in `src/styles/tokens/*.css`, loaded globally. **Full color list — nothing
outside this set is sanctioned:**

```
--oxblood-deep:#2B0A0F   --oxblood:#5A1220        --ember-a:#B33A1E
--ember-b:#E8853A        --terracotta:#C06B4A      --olive:#4A5726
--parchment:#F0E2CE      --ivory:#FBF7F0           --ink:#1E1714
--sage-soft:#CBD6C4      --honey:#F2C14E           --evidence-blue:#0E86C4
```
- `--olive` exists specifically for Root Map's 3-layer trace (terracotta/
  olive/oxblood = symptoms/conditions/roots depth), not a general-purpose
  color.
- Gradient is sanctioned for **primary CTA only**: `--gradient-ember` (135deg,
  terracotta → ember-a → ember-b).
- Oxblood is **the only place dark appears** — deep surfaces
  (`--surface-deep*`), never the page background.
- Body text is always `--ink` on every canvas stop, no text-color flipping —
  the canvas is tuned to stay ivory-first (okL 0.89–0.98) specifically so ink
  text never drops below ~12.5:1 contrast anywhere on the scroll.

**Spacing** (`spacing.css`): `--sp-1:4px` through `--sp-40:160px` on a roughly
4/8/12/16/20/24/32/40/48/64/80/96/128/160 scale. `--gutter-mobile:20px`,
`--gutter-desktop:64px`, `--container-max:1200px`, `--tap-min:44px`.

**Typography** (`fonts.css` + `typography.css`): `--font-display:'Fraunces'`
(serif, headings), `--font-body:'DM Sans'`, `--font-mono:'DM Mono'` (eyebrows,
prices, badges/numerals). Fraunces is loaded with optical-size axis
(`opsz,wght`) — it's meant to look different at small vs. large sizes, that's
intentional, not a bug. Display headings use `font-weight: 400` (NOT bold —
Fraunces reads as confidently editorial at regular weight; this repo's own
pattern everywhere, e.g. `.hook-heading`/`.treat-heading` are both
`font-weight: 400`).

**Motion** (`motion.css`): `--dur-micro:160ms`, `--dur-base:320ms`,
`--dur-scene:720ms`, `--ease:cubic-bezier(.2,.7,.2,1)`,
`--ease-out-soft:cubic-bezier(.16,1,.3,1)`. `--pin-max:200vh` (a documented
intent — never pin a scrollytelling section longer than 2 screen-heights of
scroll). Full `prefers-reduced-motion: reduce` support is wired at the token
level (durations collapse to ~0) — any new scroll-driven CSS transition
should be added to the relevant reduced-motion block too (see pattern in
`home.scss` — every new pinned mechanic this project has added also added its
own line to the `@media (prefers-reduced-motion: reduce)` block).

**Elevation** (`elevation.css`): `--r-xs:6px` … `--r-xl:32px`, `--r-pill:999px`.
`--shadow-soft:0 2px 10px rgba(43,10,15,.10)` is the standard card lift used
everywhere (e.g. `.treat-node-image`'s shadow is a hand-tuned variant of this
same idea, not a new token).

**Canvas stops** (`canvas.css`): one chained sequence, each section's `--to`
is the next section's `--from`, interpolated via CSS `color-mix(in oklab, …)`
— current order: hero → hook → treat → descent → turn → levels → team →
close. If you add a new section between two existing ones, you must thread
a new from/to pair into this chain (don't just reuse a neighbor's stops) or
the crossfade will jump.

## House rules (CLAUDE.md — read it, this is the short version)

- Standalone components, **no `standalone: true`** (default in v20+), **no
  explicit `ChangeDetectionStrategy.OnPush`** (default in v22+).
- Signals for everything: `input()`/`output()`/`model()`, `computed()`,
  `linkedSignal()` where derived from multiple reactive sources.
- `@if`/`@for`/`@switch`, never `*ngIf`/`*ngFor`. No `ngClass`/`ngStyle` — use
  `[class]`/`[style]` bindings.
- No `CommonModule` import — import only what's used (`NgOptimizedImage`,
  `NgTemplateOutlet`, `AsyncPipe`, etc., named explicitly in `imports: []`).
- `NgOptimizedImage` for all static images (`ngSrc` + `fill` inside a sized
  positioned ancestor) — used throughout Hook/Treat/Root-Map images.
- `inject()`, not constructor injection.
- Must pass AXE / WCAG AA (contrast, focus, ARIA) — this is why canvas tokens
  are tuned the way they are, and why decorative illustrations consistently
  get `alt=""` + `aria-hidden="true"` on their wrapper with a separate
  `<p class="sr-only">` describing the actual content alongside them (see
  every `treat-node-visual`/`stepIllustration` block).

## The Treat section — full architecture (this session's main work)

`home.ts`/`home.html`/`home.scss`, inline in the `Home` component (not a
separate component, consistent with how Hook is also inline rather than
extracted).

### Data model
```ts
interface TreatStep { readonly title: string; readonly body: string; readonly bodyShort: string; }
```
`body` = full mobile-length copy. `bodyShort` = desktop-only, and is **not**
just "trimmed a bit" — it's deliberately tuned so the four steps render at
**exactly one fewer line each** at the live desktop column width (4/3/2/1
lines). That's what produces the "step" visual effect: each node's image
naturally sits a little higher than the one before it, purely because its
text is shorter — **not** because anything forces the images into row
alignment (that was tried and explicitly reverted, see "Corrections" below).
If you ever edit `bodyShort` copy, re-measure the line counts afterward (see
the Playwright verification workflow below) — it's easy to accidentally
collapse the staircase back to e.g. 5/4/3/1 or 3/3/2/1.

`treatDesktopImages`: 4 landscape (1376×768, 16:9) images in
`public/images/treat-step{1-4}-laptop.png`. `stepIllustration` ng-template
(mobile-only now) still references the older portrait images
(`treat-step{1-4}-{nutritionist,bloodtest,food,checkins}.png`, 768×1376).

### Two entirely separate scroll mechanics, one shared heading template

- `<ng-template #treatHeading>` and `<ng-template #stepIllustration>` are
  declared once near the top of the `<section class="scene treat">`, used via
  `*ngTemplateOutlet` by **both** branches below. Angular template reference
  variables are visible anywhere in the same component template regardless
  of DOM nesting — this is relied on deliberately (see "Corrections" below,
  the heading-row misalignment bug).
- **Mobile** (`!treatHorizontal()`): `.treat-pin` → `.treat-viewport` (sticky)
  → `.treat-deck` → 4 stacked `.treat-deck-card`s that crossfade in place
  (plateau+fade, symmetric — fades in AND out as you scroll past). Heading
  sits in normal flow **above** the pin, scrolls away before the pin engages.
- **Desktop** (`treatHorizontal()`, ≥900px): `.treat-pin-desktop` →
  `.treat-viewport-desktop` (sticky) → heading **and** `.treat-timeline` (4
  `.treat-node`s laid out left-to-right) both inside the same sticky
  viewport, so the heading stays on screen the whole time, same as Hook.
  One-sided reveal (ramps 0→1 as its turn comes, then **stays at 1**, no
  departure fade — all 4 end up visible together, unlike mobile's
  crossfade-and-replace).

### Key constants (`home.ts`)
```
TREAT_DRAG_PHASE = 0.82            // mobile: trailing scroll "hold" after last card
TREAT_CARD_PLATEAU = 0.45          // mobile: full-opacity window width
TREAT_CARD_FADE = 0.55             // mobile: fade-in/out width (PLATEAU+FADE must = 1)
TREAT_CARD_PARALLAX_PX = 20        // mobile: card rise/translate on transition
TREAT_ILLUSTRATION_STRETCH = 1.6   // mobile: illustration gets its own, narrower
                                    //   visibility window nested in the card's wider one
TREAT_COPY_MAX_BLUR_PX = 6         // mobile: blur-on-fade for text+badge during crossfade
treatVhPerStep = 95                // mobile: scroll distance budget per step

TREAT_DESKTOP_DRAG_PHASE = 0.82    // desktop: same trailing-hold idea
TREAT_NODE_RISE = 0.6              // desktop: how much of a node's reveal window is "rising in"
TREAT_NODE_RISE_PX = 24            // desktop: rise distance
treatDesktopVhPerStep = 70         // desktop: scroll distance budget per step
```

**CRITICAL — plateau+fade math** (applies to both Hook and Treat's mobile
crossfades): plateau + fade must sum to exactly 1.0, **and plateau must stay
under 0.5**, or adjacent cards' full-opacity windows overlap and you get
simultaneous full-opacity "garbled double-exposed text." This was a real bug
this session (plateau was briefly, mistakenly, 0.75) — if you ever retune
these for "more reading time," increasing plateau past 0.5 will reintroduce
it. Hook uses `0.4/0.6`, Treat mobile uses `0.45/0.55` — both safely under the
line.

### CSS structure worth knowing
- `.treat-node-copy { display:flex; flex-direction:column; gap: var(--sp-3) }`
  — title→body and body→image gaps are **both** `var(--sp-3)` (12px),
  deliberately uniform. Don't add a `min-height` here to force row alignment
  across columns — that was tried and reverted (see below).
- `.treat-node-title { min-height: 2.5em }` — this one **is** intentional and
  kept: it reserves 2 lines so all 4 badges+titles start on the exact same
  row regardless of how any one title wraps. This is different in kind from
  the image-alignment min-height that got removed — titles/badges should
  align (that's "the heading row"), but each column's overall height below
  that should NOT be forced to match.
- `.treat-node-image { width: min(100%, 280px); aspect-ratio: 16/9;
  border-radius: 12px; box-shadow: … }` — identical for all 4 nodes.
  `.treat-node:first-child .treat-node-image { box-shadow: none }` — step 1's
  image already has its own baked-in macOS window chrome (traffic lights),
  which reads as "lifted off the page" on its own; stacking a drop-shadow on
  top of that doubled the effect, so step 1 specifically has it removed.
- `.treat-node-img { object-fit: cover }` (not `contain`) — steps 2-4 are
  full-bleed images that exactly fill 16:9 so cover/contain look identical
  for them, but step 1's laptop-window image originally sat on a canvas
  slightly narrower than 16:9 with transparent margins; `contain` let those
  margins show through as the card's ivory background (visible white bars
  beside the laptop). `cover` scales to fill and crops the margin away
  instead. (The step 1 image has since been replaced with a proper full-bleed
  version too, but `cover` was kept since it's a safe default either way.)
- `.treat-timeline { max-width: var(--container-max); padding-inline:
  var(--gutter-desktop) }` — **must** match `.treat-heading-row`'s own
  max-width/padding exactly (see the alignment bug below for why).
- `.treat-viewport-desktop { justify-content: flex-start }` with
  `.treat-heading-row { flex: 0 0 auto }` and `.treat-timeline { margin-block:
  auto }` — this combination pins the heading right under `padding-top`
  (deterministic position) while letting the timeline absorb whatever space
  is left and center itself in it. See "Corrections" for why this isn't
  simply `justify-content: center` on the parent.

## The Hook section — relevant parts for comparison/reuse

Hook is the **reference implementation** Treat's desktop mechanic was
deliberately built to match, structurally:
- `.hook-pin.is-horizontal` sits **directly under `.scene.hook`**, NOT inside
  a `.scene-inner` wrapper — it owns the full section width itself and does
  its own single-level `max-width`/gutter centering via `.hook-heading-row`.
- `.hook-viewport { justify-content: center }` works correctly there (unlike
  Treat's original mistake) because `.hook-deck { flex: 1 }` absorbs all the
  leftover vertical space itself — the heading-row, having no flex-grow, is
  pinned in practice even though the property says "center."
- `HOOK_HORIZONTAL_BREAKPOINT = 900` — the single breakpoint controlling
  desktop-vs-mobile branching for **both** Hook and Treat
  (`treatHorizontal()` reads the same constant via `Home.HOOK_HORIZONTAL_BREAKPOINT`,
  not a separate Treat-specific breakpoint — keep it that way, a mismatch
  between the two sections' breakpoints would look broken mid-resize).

## Corrections made this session (read before repeating a "fix")

These are documented in code comments at the relevant CSS/TS lines too, but
worth having in one place:

1. **Heading-row horizontal misalignment vs. Hook (the big one).** Treat's
   desktop pin was originally nested inside `<div class="scene-inner
   treat-inner">`, which already applies `max-width`/`padding-inline`. The
   heading row and timeline then applied their *own* max-width/padding on
   top of that, double-constraining the content and shifting it ~64px right
   of where Hook's identically-styled heading sits. **Fixed** by moving the
   desktop branch (`.treat-pin-desktop`) to be a direct sibling of
   `.scene-inner`, outside it entirely — exactly how Hook's `.hook-pin.is-
   horizontal` is structured. Verified via Playwright: both sections'
   heading rows now measure pixel-identical (`x`, `y`, `width`, `height`,
   font-size) at a real scroll-pinned state. **Lesson:** when a pinned
   section's layout looks subtly "off" vs. a sibling section that's supposed
   to match it, check how many ancestor elements are applying width
   constraints before touching any single rule — the bug was structural
   nesting, not a wrong CSS value.
2. **Image row-alignment was a wrong turn, then corrected.** In response to
   "steps 3 and 4 don't read as steps," a `.treat-node-copy { min-height:
   190px }` was added to force all 4 images to start at an identical row,
   on top of also writing genuinely shorter text per step. The user
   explicitly corrected this: images should **not** be forced into alignment
   — only the *internal* gaps (title→body, body→image) need to stay
   consistent; the natural height difference from shorter text **is** the
   desired staircase effect. The `min-height: 190px` rule was removed.
   **Lesson:** "make it look like a sequence of decreasing steps" can be
   satisfied by letting natural content height vary — don't reach for a
   layout-forcing property (`min-height`, `align-items: center` across
   columns) when the ask is about relative proportion, not fixed alignment.
3. **Plateau value regression** (see constants section above) — caught via
   a real-device screenshot showing garbled overlapping text, not caught by
   local review of the math alone. Reinforces: always verify scroll-driven
   opacity math with an actual sampled screenshot at the midpoint, not just
   by reading the formula.
4. **`viewChild` string mismatch** (from earlier in this session, before this
   handoff's starting point, but worth repeating since it's an easy trap):
   `viewChild<ElementRef>('treatDesktopPin')` querying for a template ref
   that was actually named `#treatPinDesktop` (word order reversed) — no
   compile error, `viewChild()` just silently returns `undefined` forever,
   and every downstream signal reading it gets stuck at its initial value.
   If a scroll-driven signal seems permanently stuck at 0 with everything
   else apparently correct, check the `viewChild` query string character-
   for-character against the template's `#ref` name first.

## Working style / process notes for a new session

- **Playwright verification loop** used dozens of times this session for
  anything involving scroll position, opacity math, or pixel alignment:
  `npm install --no-save playwright && npx playwright install chromium`,
  write a throwaway script to the repo root, `node script.js`, read
  screenshots back with the Read tool, then **always** clean up:
  `rm -f *.js *.png && npm uninstall playwright && git status --short
  package.json package-lock.json` (confirm clean). Don't skip the cleanup
  step or leave diagnostic scripts committed — a couple of these did slip
  into a prior commit and had to be deleted as cleanup in this session.
  Dev server: `npx ng serve --port 4300` backgrounded, poll with `curl` until
  it returns 200 before running Playwright against it.
- **Measuring scroll-pinned state correctly**: don't scroll by a fixed pixel
  amount and assume the pin has engaged — poll
  `document.querySelector(sel).getBoundingClientRect().top` in a loop until
  it's within ~1px of 0, *then* measure/screenshot. A fixed scroll amount
  landed mid-engage gave misleading measurements more than once this
  session (including one false alarm that looked like a real heading-
  alignment bug but was actually the `.reveal` class's own
  `translateY(28px)` entrance animation not having finished yet — always let
  `.reveal` elements settle, or explicitly check `.is-visible` is already on
  the element, before trusting a position measurement).
- **The user iterates in small, concrete, often-contradicting steps** — e.g.
  "give it more reading time" followed later by "reduce scroll effort,"
  or "force images to align" followed by "no, don't force them to align."
  Don't treat an earlier instruction as a fixed constraint if a later one
  clearly supersedes it for the same element — but do keep both the old
  rationale and the correction in code comments (as done throughout
  `home.ts`/`home.scss` this session) so a future reader - human or AI -
  doesn't re-introduce the earlier approach thinking it's an oversight.
- **Image generation workflow**: the user generates images externally (not
  via this session) and drops them in
  `C:\Users\Admin\Downloads\Nutri\ai-generated-images\`, then asks to "find
  and replace" by filename/tag (e.g. "with bg_removed tag," "try this image
  then @path"). This session's job in that handoff is: locate the file(s),
  visually inspect with Read before copying (check dimensions, transparency,
  whether it's full-bleed vs. inset-card style), copy into
  `public/images/` under the **existing** filename the component already
  references (don't rename component-referenced paths unless asked), then
  verify via Playwright screenshot. When asked to *write* generation
  prompts (not generate images directly — this environment can't), match the
  established style exactly: flat vector illustration, warm terracotta/
  oxblood/cream palette, hand-drawn line-art with soft shading, and
  explicitly call out full-bleed-to-the-edge framing if that's what's needed
  (steps 2-4's first draft had the opposite problem: an inset card floating
  on a separate flat background, which visually clashed with step 4's
  full-bleed treatment — spell out "fills the entire frame edge-to-edge, no
  border, no outer margin" explicitly in the prompt if that's the goal).
- **`angular.json` CSS budget**: `home.scss` has grown across both the Root
  Map and Hook/Treat work. Current `anyComponentStyle` budget:
  `maximumWarning: 16kB`, `maximumError: 28kB` (raised from 8kB/12kB across
  several rounds this project). Current actual size produces a non-blocking
  warning (~21kB). If it keeps growing, the next move is probably actually
  splitting `home.scss` per-section rather than raising the budget again.
